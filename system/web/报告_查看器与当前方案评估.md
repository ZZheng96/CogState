# EEG 查看器与当前方案评估（2026-11-06）

> **已过时（2026-11-08）**：文中 E42/E44/E87/OOF 方案及 build_e44.py 等已从系统移除，系统改为自包含（system/algorithms/）。当前指标见 `system/报告_57人全量训练指标.md`。

## 结论

当前方案（`src/infer.py`）在 57 名被试上的结果如下。按每秒一个决策、6 s 因果感受野计算，指标先按被试求出，再做宏平均。

| 输出 | bACC | AUC | F1 | bACC ≥0.9 人数 |
|---|---|---|---|---|
| 单窗原始得分（raw） | 0.933 | 0.982 | 0.932 | 48/57 |
| 后处理（EMA 去趋势 + 前向 HMM，post） | **0.947** | **0.989** | **0.947** | **56/57** |

**注意：这是训练集内指标。** `model_bundle.pt` 用全部 57 人训练，所以上表反映的是拟合程度，不代表对新被试的泛化能力。跨被试 5 折的参考成绩是 bACC .762 / AUC .823 / F1 .761（见 `test/17_compliant/报告_E17_合规方案.md`）。

## 使用方法

- 双击仓库根目录的 `启动EEG查看器.bat`。浏览器会自动打开 http://127.0.0.1:8765/ 。关闭命令行窗口即停止服务。如果服务已在运行，脚本只打开浏览器。
- 也可以在命令行运行 `.venv\Scripts\python.exe system\web\viewer_server.py`。
- 首次运行前，建议先执行 `.venv\Scripts\python.exe system\web\model_eval.py --all` 预计算全部被试，结果缓存到 `system/web/cache/pred_<sid>.npz`。没有预计算的被试会在第一次打开时由后台计算。

## 决赛验证系统（http://127.0.0.1:8765/system）

后端代码在 `system/`，用标准库 HTTP + SSE 实现，没有新增依赖。前端是 `system/web/system.html`。

**指标是重算还是读缓存？** 系统中显示的指标全部由 `system/evaluate.py` 重新计算。计算时，方案只提供逐帧的 (t, score)，标签由 `system/truth.py` 根据 BDF 和 events 独立生成，不使用方案自带的 y。只有分数可能来自缓存：评估页的"来源"列标明了每个分数取自 runner 缓存（`system/cache/runs/`）、离线 npz，还是本次在线计算。如果选择 live 模式，所有分数都会重新流式计算。

| 页面 | 功能 |
|---|---|
| 实时回放 | 按块（0.1–5 s）把 BDF 喂给方案，方案每 1 s 输出一帧，通过 SSE 推到前端；同时显示累计 bACC/AUC/F1、延迟和 6 s 感受野波形。速度可选 1×（实时）到不限速 |
| 批量评估 | 支持多方案对比。取数模式可选 auto、live、cache；结果写入 `reports/eval_*.md` |
| 合规检查 | 检查分块一致性、前缀一致性（未来数据不能影响过去的输出）、输出时延、6 s 感受野、历史依赖和实时性；结果写入 `reports/compliance_*.md` |
| 数据与训练 | 导入新数据目录（`data_import/<名称>/`）后，勾选被试重训，模型保存到 `models/<名称>.pt`，并自动注册为方案 `m_<名称>` |
| 导出提交 | 动态追踪推理依赖闭包，打包到 `exports/<包名>/` 和 `.zip`。包内自检项：依赖自足、与系统输出逐帧一致、由输出 CSV 独立计算指标、合规检查 |

验证结果如下：
- 全量缓存评估，current 方案：bACC 0.9473 / AUC 0.9894 / F1 0.9469（57 人，训练集内）。
- 全量缓存评估，e44 方案：bACC 0.7830 / AUC 0.8321 / F1 0.7748（LOSO）。
- current 方案合规检查全部通过，RTF 33×。
- 导出包自检（current，被试 018）全部通过：包内运行与系统输出的最大差为 4.8e-7，bACC 0.9728 / AUC 0.9953 / F1 0.9727。

新设备的数据目前通过文件回放接入。真实设备只需实现与 `system/runner.py` 中文件源相同的分块读取接口。

## 波形查看器功能

- 白色主题。左侧列出被试，最多可同时选 6 人，每人一道波形，所有道共用时间轴。列表右侧的数字是该被试的方案 bACC。
- 黄色带状窗口表示 6 s 感受野 [t−6, t]，可以拖动。单击波形设置判断时刻 t，按 F 把视图居中到窗口。
- 下方 zoom 面板显示窗口内的原始波形和 1–45 Hz 因果滤波后的波形。
- 每道波形下方有两条：方案逐秒得分条（红色为 task，蓝色为 relax）和真值条。
- 右侧信息栏不出现滚动条，包含四张卡片：方案说明、总体与当前被试指标、判断时刻的输出、频带功率。
- 被试列表顶部有"▲ 上一个 / 下一个 ▼"按钮，快捷键是 `[` 和 `]`。按下后，高亮道会换成列表中相邻的、还没被选中的被试。
- 顶部的 A/B 下拉框用来切换方案。B 选中某个方案后进入对比模式：每道下方的得分条分成上下两半，上半是 A，下半是 B；指标表增加 B 列和 Δ(B−A) 列；被试列表增加 Δ bACC 列。

E42/E44 方案由 `system/web/build_e44.py` 生成：它读取 `test/42_e17_loso_hmm/e42_scores.npz`（57 人 LOSO 逐帧分数），在 GPU 上计算两种后处理，帧时间和标签取自 `sliding1/sub-<sid>.npz`，结果写入 `system/web/cache/e44/`。指标与 E44 报告一致。E44 相对 E42 的变化是 bACC +0.5、F1 +1.4 个百分点，≥0.9 的人数少 1 人。

跨被试方案由 `system/web/build_oof.py` 生成：按照 E17 的 5 折划分（`RandomState(0)` 置换），每折各训练一个不含本折被试的 bundle，再用它预测本折被试，结果写入 `system/web/cache/e17_cv/`。

## 为什么 E17 / 当前方案的指标这么高

方案里**没有被试专属参数**。全部被试共用同一个 `model_bundle.pt`，后处理参数也是全局统一的。指标高的原因有三个：

1. **训练集内评估。** bundle 用全部 57 人训练，被评估的被试就在训练集里。这一项影响最大：跨被试 CV 只有 bACC .762。
2. **多尺度因果滑动标准化。** 每个被试的特征会用他自己过去 60–∞ 帧的均值和方差做归一化，相当于无监督的个体自适应。这一步不用标签、不看未来，CV 的结果里已经包含了它的贡献。
3. **后处理。** EMA 去趋势（hl=1200 s）和 HMM（dwell=300 s）利用了 trial 都很长（约 5 min）这一点。E17 报告的合规口径规定"决策之间不做分数平滑"，所以 post 列已经超出了 E17 报告的口径。在训练集内，post 比 raw 高 +.014 bACC。

## 评估口径

- 每 1 s 输出一个决策，窗口为过去 6 s。只有当 [t−6, t] 完整落在同一个 trial 内且不含缺失段时，这一帧才计入指标。
- score > 0 判为 task。AUC 直接用连续得分计算。
- raw 是 StreamingInference 的单窗得分。post 是在 raw 上依次做因果 EMA 去趋势（hl=1200）和前向 HMM（dwell=300）。
